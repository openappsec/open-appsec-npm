## C. Build pipeline state

The fork has no `Jenkinsfile`; CI is driven externally or absent. The
end-to-end local build is:

```bash
# 1. Frontend build
cd frontend
npm install              # or: yarn install
npm run build            # produces frontend/dist/

# 2. Docker image build
cd ..
docker build -f docker/Dockerfile -t open-appsec-npm:2.14.0-appsec.1 .

# Optional: central-management image
docker build -f docker/Dockerfile.central-mgmt \
    -t open-appsec-npm-central:2.14.0-appsec.1 .

# 3. Bring stack up
cd deployment
docker compose up -d
```

## D. Open issues / minor concerns

Items deliberately left for follow-up because they did not block release:

1. **Empty-state i18n on log tabs (Phase 6 minor).** The four log tabs
   (`All`, `Important`, `Detailed`, `Notifications`) render hard-coded English
   empty-state strings rather than `t(...)` keys. Low-risk cosmetic gap.
2. **Modal field labels in `OpenAppsecFields.tsx` (Phase 4–5 minor).** Some
   labels and helper text in the open-appsec config tab inside
   `ProxyHostModal` remain English-only.
3. **Vite chunk size warning.** The main bundle (`index-CQiS7jVD.js`) is
   ~2.3 MB / 716 KB gzip. Pre-existing; not introduced by this port. Worth
   addressing eventually via `manualChunks`.
4. **`docker/lib/*.so` binaries committed.** These ABI-locked attachment
   libraries live in the tree (necessary for the build but heavy). README's
   "compiling against other NGINX versions" section documents how to rebuild.
5. **Phase 1 reviewer flagged `backend/package.json#version` (`2.0.0`).**
   Resolved in Phase 7 — bumped to `2.14.0-appsec.1` to match `.version` and
   match the convention of the prior fork release (`7f11a051` used
   `"2.12.3"`).
6. **`frontend/.yarn/` and `frontend/.yarnrc.yml` are untracked** in the
   worktree (left over from local tooling). Confirm `.gitignore` covers them
   before any future commit.

## E. Runtime smoke checklist for the user

These must run on a Docker-capable host. They are the **first** validations
to perform after pulling `align-2.14`:

- [ ] `docker build -f docker/Dockerfile -t open-appsec-npm:2.14.0-appsec.1 .`
      completes successfully.
- [ ] `docker build -f docker/Dockerfile.central-mgmt
      -t open-appsec-npm-central:2.14.0-appsec.1 .` completes successfully.
- [ ] `cd deployment && docker compose up -d` brings up `npm-attachment` and
      `appsec-agent` healthy; admin UI reachable on `http://localhost:81`.
- [ ] Backend migrations run cleanly against a fresh SQLite DB — verify
      `backend/migrations/20260513120000_open_appsec.js` applies without
      error (check the migration entry appears in the `migrations` table).
- [ ] Cypress e2e suite (`./scripts/ci/fulltest-cypress`) passes against the
      built image.
- [ ] **WAF activation curl test:** create a proxy host via the UI, enable
      open-appsec on it, send a request matching a known attack signature
      (e.g. `curl -i 'http://<host>/?id=1%20OR%201%3D1--'`), confirm the
      agent returns a block response.
- [ ] **Open-appsec log streaming:** confirm log entries appear in the four
      tabs (All / Important / Detailed / Notifications) and the details modal
      opens correctly for a blocked request.
- [ ] Smoke-test the open-appsec config tab inside `ProxyHostModal` — toggle
      on/off, change settings, save, reload, confirm persistence.
- [ ] Smoke-test per-location overrides (`LocationsFields.tsx`) — set a
      different policy per custom location, confirm nginx config writes
      reflect the override.

Until every box above is ticked, the build is code-complete but not
runtime-validated.
